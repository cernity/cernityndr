# 004 — SIEM packs: portable source of truth + deterministic native build

Status: accepted (Increment 3, Unit U8)

## Context

U8 ships SIEM content packs (Splunk, Elastic, OpenSearch). The r1 implementation authored
every dashboard/pivot in one bespoke JSON shape (`inputs`/`panels`/`drilldowns` with
`canonical` + `pivot_field`). That shape is machine-checkable against
`contracts/siem_pivot.schema.json` — which is the whole point of the U8 gate — but **no SIEM
can consume it**: Splunk imports Simple XML / Dashboard Studio definitions, Kibana and
OpenSearch Dashboards import saved objects. Peer review (codex) blocked on this: the documented
"native import" workflow could not consume the packaged format because no converter existed.

Two options:

- **A. Hand-author native artifacts** — Simple XML per Splunk dashboard, saved-object NDJSON
  per Kibana/OpenSearch object, a native Kibana rule. Correct, but 3× fiddly formats to keep in
  lock-step with the field-reference gate by hand.
- **B. Portable source + deterministic renderer** — keep the portable defs as the single source
  of truth (so the field-reference gate stays tractable and one edit covers all three platforms)
  and add `deploy/siem/build.py`, which renders the native artifacts. This is exactly the
  "deterministic build step producing them" the reviewer offered.

## Decision

Option B. The portable defs under `deploy/siem/<platform>/…` are source; `build.py` renders
platform-native artifacts into `deploy/siem/dist/`:

- Splunk → Simple XML `<form>` dashboards (drilldowns use the native `|u` URL-encode token
  modifier; evidence links are computed in-search with `isnull` guards).
- Elastic / OpenSearch → saved-object NDJSON (search + URL drilldowns; external evidence links
  use the `encodeURIComponent` handlebars helper).
- Elastic detection rule → a native Kibana Security **threshold** rule (authored natively, copied
  by the build).
- Elastic assets are also emitted in a Fleet **integration package layout**
  (`dist/elastic/cernity_ndr/{manifest.yml,changelog.yml,docs,kibana,elasticsearch}`).

The gate (`deploy/siem/test_packs.py`) validates the portable source (field references, drilldown
bindings survive their panel's aggregation, destinations resolve), imports `build.py` to validate
the **rendered** native artifacts parse to their platform schema, and renders the representative
finding through the pivots. Negative cases assert the gate rejects an unknown field, a missing
destination, and an occurrence id removed by aggregation.

## Consequences

- One portable edit updates all three platforms; the renderer is the only place native syntax lives.
- Evidence destinations are configurable (`MANIFEST.json.evidence.base_url`), identifiers are
  URL-encoded, and null ids produce no link (explicit null handling), on every platform.
- `dist/` is a build output; it is regenerated by `build.py` and validated in CI, not hand-edited.
